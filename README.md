# Buildora AI

Лендинг (`index.html`) + Telegram-бот (`bot.js`) для приёма заявок на разработку сайтов, чат-ботов, приложений и автоматизации.

## Сайт (index.html)

Один самодостаточный HTML-файл (логотип встроен как base64, внешних файлов не требует) — можно открыть локально или захостить на любом статическом хостинге (GitHub Pages, Netlify, Vercel).

Перед публикацией замените в конце файла `index.html` значение `BOT_USERNAME` на username вашего бота (без @) — тогда кнопка «Отправить в Telegram» будет вести на правильный чат и сразу открывать нужный раздел.

## Возможности

- Главное меню с 4 кнопками: сайт / чат-бот / приложение / контакты
- Приём идеи текстом от пользователя и пересылка заявки админу
- Ответ администратора пользователю прямо через Reply в Telegram
- Таймаут ожидания идеи (сброс состояния через 15 минут)
- Защита от флуда (лимит сообщений в единицу времени)
- Команды `/start`, `/menu`, `/help`
- Уведомление пользователя, если у него уже есть необработанная заявка

## Установка

```bash
git clone <ссылка на ваш репозиторий>
cd buildora-bot
npm install
```

## Настройка

1. Скопируйте `.env.example` в `.env`:

   ```bash
   cp .env.example .env
   ```

2. Заполните `.env`:

   - `BOT_TOKEN` — токен бота, полученный у [@BotFather](https://t.me/BotFather)
   - `ADMIN_CHAT_ID` — ваш chat_id (узнать можно у [@userinfobot](https://t.me/userinfobot)), сюда будут приходить заявки

## Запуск

```bash
npm start
```

## Как отвечать пользователям

Когда приходит заявка, сделайте **Reply** прямо на это сообщение в Telegram и напишите текст ответа — бот автоматически перешлёт его нужному пользователю.

## Ограничения текущей версии

Все состояния (кто что вводит, какие заявки ещё без ответа) хранятся в памяти процесса. При перезапуске бота эти данные сбрасываются. Для продакшена рекомендуется добавить хранение в базе данных или файле.
